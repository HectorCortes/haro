# Exploration: 2026-09-11-v2-broker-ipc — per-project broker, JSON-RPC IPC, interaction skeleton

> **Change**: `2026-09-11-v2-broker-ipc` — Step 3 of the supervised plan.
> **Mode**: `both` (OpenSpec + Engram). Hybrid delivery `single-pr` with `size:exception` (200k budget), direct push to `main`, Strict TDD (`go test ./...` active). Pure Go, no cgo (`modernc.org/sqlite`), JSON-RPC over Unix socket (named pipe Windows), YAML workflows. 15 packages green.
> **Out-of-scope for this change**: Supervised runtime (supervisor engine, real permission mediation, bundles/admission, enabling `mode: supervised` — runtime guard stays active), Terminal/PTY, Resume/reconciliation (`v2-no-regresion/F-06`) unless criteria force it.

## Current State

### Normative contract

- **Constitution** (`docs/v2/haro-constitucion.md`): IV.1 defines Broker as per-project daemon bridging CLI and adapters; VII.1–VII.3 fix CLI↔Broker as JSON-RPC/UDS (named pipe Windows), one broker per project (canonical path), lazy startup + retry, multi-session concurrency within one project, zero cross-project coordination; VI governs lifecycle + fencing (only holder of current lease may write; expired lease via `fencing_token` makes later writes invalid even if origin process lives); VIII defines event/cursor model (monotonic per session/attempt, no raw payload, idempotent `approve`, fail-closed permission). IX/X are reuse-only (path_claims, composition) — must not regress.
- **Tech spec** (`docs/v2/haro-especificacion-tecnica.md`):
  - §2 DDL already canonical: `projects`, `executions` (with `dag_hash`, `base_commit`), `execution_steps`, `generations`, `attempts`, `attempt_transport`, `leases(execution_id, step_id, holder, fencing_token, expires_at PK(execution_id,step_id))`, `step_transition_events(execution_id,step_id,cursor UNIQUE)`, `attempt_events(attempt_id,cursor UNIQUE, payload_ref, payload)`, `interactions(id, attempt_id, type, status, decision, idempotency_key UNIQUE(attempt_id,idempotency_key))`, `path_claims`. All `TEXT` times ISO 8601 UTC, `WAL` + `FK ON`. Payload doctrine §2.1: `payload` sanitized/bounded delta, never raw; `payload_ref` external/legacy only (VIII.2).
  - §6 CLI↔Broker method table (normative for this change): `execution.start{workflow_path, workspace_override?}→{execution_id}`, `execution.status{execution_id}→{status, steps[]}`, `execution.report{execution_id}→{changed_files}`, `step.run{execution_id, step_id, mode?:"headless"|"supervised"}→{attempt_id, cursor}`, `step.events{execution_id, step_id, since_cursor}→{events, next_cursor}`, `step.approve{execution_id, step_id, interaction_id, decision, idempotency_key}→{resolved}`, `step.cancel{execution_id, step_id}→{}`, `step.reopen{execution_id, step_id}→{invalidated}` + notifications `step.status_changed` / `step.interaction_required`. Mode is additive, not a closed enum (IV.2); `supervised` stays gated until step 4.
  - §7 ACP: broker↔adapter is ACP-shaped (`initialize` once, then `session/new|prompt|update|cancel|request_permission`, optional `load/terminal/*`). Managed-session decision: **broker will consume ACP at broker↔adapter edge in the future supervised step** — broker's adapter-facing surface should not preclude it, but ACP server dispatch is **OUT** of this change. Adaptation stays CLI-direct (`engine.SetAdapterManager` today).
- **Deltas** (`deltas-acceptance.md` preamble + criterion tables):
  - ACP note at `:26` fixes broker↔adapter as ACP (JSON-RPC 2.0/stdio + `initialize` cap-negotiation) and adapters translate; `v2-no-regresion/F-09` describes the supervised complete that this change precedes (leases+fencing, UDS IPC, cursor-persisted-before-visible, idempotent CAS, `step approve` with `available_decisions`, fail-closed) — context, not scope.
  - `v2-broker` (9 criteria, lines 160–198): F-01 single broker / canonical path / UDS; F-02 lazy startup + retry + outlives CLI; F-03 concurrent sessions; F-04 independent per-project brokers; F-05 no duplication; F-06 death+fencing; F-07 clean shutdown; U-01 socket path derivation (stable hash, length limit); U-02 robust framing (reject malformed/oversized, keep alive, concurrent).
  - `v2-ipc` (13 criteria, lines 200–254): F-01 start validates + creates execution, F-02 status, F-03 non-blocking run → `{attempt_id,cursor}` + progress via events, F-04 stable pagination, F-05 idempotent approve, F-06 cancel, F-07 reopen+invalidation cascade, F-08 reopen+feedback, F-09 notifications; U-01 monotonic cursor + persist-before-visible, U-02 interaction CAS, U-03 `payload_ref` without raw output, U-04 boundary-validated JSON-RPC payloads.

### Existing groundwork (what the change builds on)

- **IPC framing** — `internal/ipc/health.go` (`HandleConn` single-shot `{"jsonrpc":"2.0","method":"health"}`→`{"ok":true}`), `internal/ipc/jsonrpc/codec.go` (`MaxMessageSize=10 MiB`, `ID`/`Message`/`RPCError`, `EncodeRequest/Response/Error/Notification` NDJSON with `\n`, `DecodeMessage` line-oriented with `UseNumber`, size enforcement before `json.Decoder`). Tests: `internal/ipc/health_test.go`, `internal/ipc/jsonrpc/codec_test.go` cover malformed/oversized/concurrency basics. **No** long-lived server loop, no method dispatch, no socket lifecycle, no health vs full RPC demux yet.
- **Store** — `internal/store` fully supplies the domain surfaces the broker will rely on:
  - Migrations (`internal/store/migrations.go`) idempotent `IF NOT EXISTS` + transactional `migrateWithStatements` + additive `ALTER` for `dag_hash`/`base_commit`/`payload`; `internal/store/store.go` exposes `Store{Projects, Executions, Steps, Attempts, Generations, Events, Transport, PathClaims, Leases, Interactions, WithTx, Close}` backed by SQLite (`modernc.org/sqlite`) with `PRAGMA foreign_keys=ON`, `journal_mode=WAL`, `busy_timeout` handled in some arches, plus alternate `internal/store/fake.go` fake enforcing CHECK/UNIQUE/FK, monotonic cursors, RFC3339 UTC, copy-on-write `WithTx` (parities via `internal/store/contract/suite.go`, `parity_test.go`). 15 packages pass `go test ./...` / `-race`.
  - `Leases` (`internal/store/leases.go`): `Acquire` uses `BEGIN IMMEDIATE` on a dedicated `db.Conn`, `fencing_token` monotonic `MAX+1`, `expires_at = now+1m`, `Renew/Release` check `(holder,fencing_token)`, `Get` for inspection. Pattern proven but **engine does not yet use leases at runtime** for fencing — only the repository exists.
  - `Interactions` (`internal/store/interactions.go`): `Create` strict NOT NULL CHECK, `Get`, `Resolve` CAS: fetch → `idempotency_key` must equal stored key else `ErrUniqueViolation`, `resolved→idempotent return`, `pending→UPDATE ... WHERE status='pending' AND idempotency_key=?` then `RowsAffected` check + concurrent-resolve fallback to fetch-again idempotent. `UNIQUE(attempt_id,idempotency_key)` at DDL. Identity crossing (wrong attempt) is rejected by the unique constraint semantics + broker-level check needed.
  - `Events` (`internal/store/repositories.go:eventsRepo`): `CreateAttemptEvent`/`CreateTransition` insert with `cursor UNIQUE(attempt_id,cursor)` / `UNIQUE(execution_id,step_id,cursor)`, `NextAttemptCursor/NextTransitionCursor` as `COALESCE(MAX(cursor),-1)+1`, `PriorOutputDelta` ordered by `started_at DESC, id DESC, cursor DESC`, `ListTransitions` ordered by `cursor`. Payload doctrine: `payload TEXT` nullable (added via `ensurePayloadColumn`), `payload_ref TEXT` legacy; engine already writes `output_delta` inline `payload = VisibleEvidence(...)` (≤16 KiB after `Redact`) and never raw, `payload_ref` only for legacy `feedback`/`reconstruction_context` (engine path `RunStep:638-642, 998-1003`).
  - `Generations`, `Attempts`, `ExecutionSteps`, `Transport`, `PathClaims` complete; `path_claims` atomic `Acquire` with `BEGIN IMMEDIATE`, prefix-overlap scan, `ShouldBlock` 4-row matrix, owner-checked `Release`.
- **CLI today** — `internal/cmd/execute.go:Execute` is pure CLI-direct: opens `filepath.Join(cwd,".haro","store.db")` per invocation, constructs `execution.NewEngine(s, getRunner(), cwd)`, injects adapter manager once via `injectAdapterManager(ctx, eng, cwd)` at `handleRun / handleStepRun / handleStepReopen / handleStepSkip` (report unwired), then calls `eng.CreateExecution` or `eng.RunStep` **synchronously** (blocking `CommandRunner.Run` with 300 s ceiling). No daemon process, no socket, no retry/launcher. Output contract is JSON via `internal/cmd/output.go:writeJSON / writeJSONError` (EPIPE-safe, `unknown_command/invalid_argument` codes, `--` handling, `fs.Parse` per subcommand). `main.go` is `Execute(ctx, os.Args[1:], cwd, Stdout, Stderr)`.
- **Engine reuse surface** — `internal/execution/engine.go` already implements most of what a broker-hosted execution would reuse vs reimplement:
  - `CreateExecution(ctx, workflowName)` does `workflow.Discover → ValidateFile → Flatten(cycle/contract/containment checks) → ValidateFlat → Prune worktrees → captureBaseCommit(git rev-parse HEAD) → worktree.Create? → WithTx(Executions.Create + Steps.Create)` with `DagHash` stored for resync; `resolveWorkspaceForFlat` is `system→workflow→step` override (composition already **complete** — `2026-09-06-v2-composicion` archived).
  - `RunStep(ctx, executionID, stepID, feedback)` for both `command` and `agent`: `verifyDAGHash` resync, leaked `type=="workflow"` guard, `status==pending` else reconstruction via feedback, `depends_on` + `requires` (with `requiresStale` latest-generation gating), `produces` containment via `workflow.ValidateContainedPath`, `acquireClaims`/`releaseClaims` (canonicalize via `claim.Canonicalize`, `IsExternal → shared`, mode `isolated:<executionID>`), `pending→running` via `transitionStep` (audited), generation+attempt creation, `CommandRunner.Run` (argv via `ParseArgv` quoted-lexer, never shell), `CommandEvidence→VisibleEvidence` single point, inline `attempt_events` write, snapshot bounded `SnapshotBytes(1 MiB)`, exit-code & missing-produces cases, `completeAttempt`+`transitionStep`+`resyncExecution` which updates execution status and removes worktree on terminal.
  - `runAgentStep` adds: `harnessCandidates ∩ {configured,enabled,registered,Available}` ordered intersection with `probeResults` from `adapter.Manager.Probe` cache (probe-once F-01), skip-diagnostics accumulation via `FallbackEvidence(2 MiB)`, per-candidate generation+attempt+empty `Transport` row in `WithTx`, `adapter.Manager.NewSession` with `agentHost` (`SessionHost` forward — today `Record permission_requested` but always `Options[0]`), `Prompt` streaming collection until `completed/failed`, `Cancel` idempotent, `TransportProvider.SessionTransport` identity replacement (U-04), `AgentEvidence`→ single `VisibleEvidence`, `isTerminal` vs clean fallback loop, final exhaust handling.
  - What's **not** in the engine: any lease `Acquire/Renew/Release` at runtime, any interaction creation (`interactions.Create`) flow for `permission_requested` → `step.approve`, any `Cancel` RPC wiring, any non-blocking `step.run` (today fully blocking), any `step.events` host. The store has the primitives; the engine doesn't yet orchestrate them in a broker-owned long-lived mode.
- **Project layout** — `internal/project/{config.go, init.go}`: `LoadConfig` strict `yaml.Decoder.KnownFields(true)` rejecting unknown keys, `HarnessConfig{Binary, Env, TimeoutSeconds, Enabled *bool}` with defaults (`Enabled true`, `TimeoutSeconds 300`, range 1..300); `Init` idempotent `.haro/{config.yaml,workflows,skills,artifacts,docs}` `0o755/0o600`; DB lives at `.haro/store.db` (file-per-project), worktrees at `.haro/worktrees/<executionID>`, artifacts at `.haro/artifacts`, legacy `.haro/runtime/` in v1 doc but now `store.db` direct. Root canonicalization for socket/project id today is just `e.root` string — will need `EvalSymlinks+Clean` + stable hash.
- **Test posture** — `go.mod` exists (`module github.com/HectorCortes/haro`), `go test ./...` green, bench/journey corpus unrelated, docs-v2 traceability `92 criteria` (11 specs) — `v2-broker`+`v2-ipc` are the two pending specs blocking supervised. `openspec/specs/v2-ipc/spec.md` **EXISTS** but covers only the payload-doctrine amendment (U-03 narrow) with non-requirement "JSON-RPC or broker implementation is not introduced by this doctrine amendment." — will need full delta spec later. `openspec/specs/v2-broker/spec.md` **DOES NOT** exist yet (confirmed `ls openspec/specs` has no `v2-broker`).

## Gap Analysis

> Scale: **DONE** — fully implemented, meets criterion in place; **PARTIAL** — primitives exist but not wired to the broker/IPC surface; **GAP** — absent.

### v2-broker — Persistent per-project broker (9 criteria)

| Criterion | Verdict | Evidence |
|-----------|---------|----------|
| **F-01 single broker per project (canonical path, UDS/named pipe)** | **GAP** | No daemon binary, no listener, no socket-path derivation. Current `Store.Open(file:.haro/store.db)` is file-per-project but process is per CLI invocation. `const` canonicalization `e.root` vs needed `filepath.EvalSymlinks+Clean` + hash. ### Cross-cutting verdict

- **Strongest foundation**: Store (DDL+repos+fake parity) and engine DAG/claims/composition are production-grade reuse surfaces — the broker's feasibility hinges on thin orchestration, not deep refactors.
- **Biggest gaps**: The entire daemon lifecycle (F-01..F-05,F-07,U-01,U-02), non-blocking execution (F-03), and the live notification/cancel/approve surfaces (F-05..F-09) are absent — this is the "biggest deferred change" characterization; the step 3 plan sequencing is coherent.
- **Most nuanced risks**: Lease fencing wiring, cursor persist-before-visible atomicity, and socket-path length/component choice — all have prior art in v1 (`docs/reference/PROJECT_CONTEXT.md`) that must be recovered without copying TS assumptions.

## Design Tensions and Risks

| Tension / Risk | Why it matters | Mitigation sketch |
|----------------|----------------|-------------------|
| **Daemon binary boundary — same binary with `broker` subcommand vs separate `haro-broker` executable** | Single `go.mod` and single distribution (`dist/`) vs operational clarity. Spawning `os.Executable` with `haro broker --project <root>` outlives CLI and shares same socket derivation, but `log` vs CLI output, systemd-like supervision, and signal handling diverge. | Recommended: **same binary, `broker` subcommand** (`internal/broker/daemon.go`). CLI launcher `internal/broker/launcher.go:EnsureBroker(ctx, root)` does `Dial` → if ok use; else `os.StartProcess(exe, ["haro","broker","--project",canonRoot,"--socket",socketPath])` with `SysProcAttr{Setsid:true}` + env passthrough, then `Dial` retry with exponential backoff (`50/100/200 ms` akin to migrations) + stale-socket removal if `Dial` refused but file exists. Keep distribution single. |
| **Socket path length (108-byte UDS limit on Linux, shorter on macOS)** | Canonical repo path may be >90 chars; `filepath.Join(cwd,".haro","store.db")` is already long. Naive `filepath.Join(cwd,".haro","broker.sock")` exceeds limit and `net.Listen` fails with `bind: invalid argument`. | Derive `socketPath(root)` as: `canon := EvalSymlinks(Clean(root)) ; h := hex(sha256(canon))[:16] ; base := filepath.Join(os.TempDir(), "haro-"+h+".sock")` if `len(base)<100` else use `os.Getenv("XDG_RUNTIME_DIR")` fallback then `$TMPDIR/haro/...` — short, stable per project. On Windows use `\\.\pipe\haro-<h>` with `npipe` package (pure Go). Add unit table identical to archived `socket-path` expectations (symlink/trailing-slash stability). `internal/ipc/socket.go` owner. |
| **Lock vs PID file vs flock for no-duplication (F-05)** | `O_CREATE|O_EXCL` lockfile survives crashes; `flock` auto-releases on death. Choose correctly to avoid both zombie lock and duplicate daemon under thundering herd. | Lock file `filepath.Join(os.TempDir(),"haro-"+h+".lock")`; launcher: `fh, _ := os.OpenFile(lock, O_CREATE|O_RDWR, 0600)` → `syscall.Flock(fh.Fd(), LOCK_EX|LOCK_NB)` -> if fails, `Dial` again to verify liveness (stale holder died but flock auto-released). Within lock, check socket liveness once more before spawning. Release on parent exit is automatic. |
| **Fencing token semantics on broker death (F-06)** | Spec says leases expire and no write after expiration is valid even if original process lives. Today's `Acquire` never expires unless `Renew` called; `Renew` takes `(holder,token)` but engine never uses it. Need to distinguish lease ownership (broker holder UUID) from process liveness. | Broker owns leases with `holder=brokerID:uuid` and per-attempt fencing token incremented on each `Acquire`. Broker heartbeat goroutine calls `Leases.Renew` every 30s (`expires_at = now+60s`). Any store write path checks liveness: `Get(lease)` → if `now > expires_at` then reject with `ErrLeaseExpired→ RPC code -32001` and trigger `resume`-guiding error. On broker death (socket close), broker process dies without `Release`; expiry in DB naturally invalidates old token; restarted broker gets `token+1` on next `Acquire`, old token stale forever. Add `WithTx+checkToken` wrapper around `completeAttempt`. |
| **Non-blocking `step.run` vs current blocking engine** | Tech spec §6 says `step.run` returns `{attempt_id,cursor}` without blocking — agent steps are long-running. ## Suggested Approach

### Architecture sketch

```
CLI Process(s) ──Unix socket NDJSON──► Broker Daemon (per project)
  execution.start                        │
  execution.status  execution.report     │─► Store (SQLite .haro/store.db, WAL, file lock via BEGIN IMMEDIATE)
  step.run (async)                       │      Executions / Steps / Attempts / Generations / Transport / Events / Leases / Interactions / PathClaims
  step.events (poll) ◄── notifications──┤
  step.approve ◄──── step.cancel ──────►│
  step.reopen                           │
                                        │
  Broker owns: Store singleton, Lease heartbeats, Event broadcast, Adapter Manager (lazy, probe-once)
  Adapters: opencode/claude via internal/adapter/* (CMD subprocess, no shell)
```

*No supervisor, no ACP dispatch, no terminal — but broker's internal shape anticipates ACP (see “Future-proofing” below).*

#### Daemon lifecycle

- **Launcher** (`internal/broker/launcher.go`): `func EnsureBroker(ctx, root string) (net.Conn, error)`
  1. `sock := socketPath(root)` (`internal/ipc/socket.go:SocketPath`) — `EvalSymlinks+Clean → sha256 → short /tmp path` (+ Windows named-pipe branch `\\.\pipe\haro-<h>` via `github.com/Microsoft/go-winio` pure-Go fallback or `net.Listen` on Unix only with build tag).
  2. `Try Dial(sock, 2s)` → if success return conn (reuse).
  3. `lock := lockPath(root)` → `OpenFile(O_CREATE|O_RDWR,0600)` → `Flock(LOCK_EX|LOCK_NB)`; on `EWOULDBLOCK` retry Dial 3× with 100 ms backoff (another launcher won race).
  4. Inside lock: `Dial` again (double-check), if still fail: `os.Stat(sock)` exists + Dial fails → `os.Remove(sock)` (stale), then `cmd := exec.CommandContext(detachCtx, os.Args[0], "broker", "--project", canon, "--socket", sock)` with `SysProcAttr{Setsid:true, Setpgid:true}` + `Stdout/Stderr → /dev/null` or `.haro/broker.log`, `Stdin=nil`; `cmd.Start()` (DO NOT `Wait()`)
  5. Poll `Dial` 10× with `50ms·2^n` backoff. On success release flock and return conn; else fail with `launch_failed` code.
- **Daemon** (`internal/broker/daemon.go:RunBroker(ctx, root, sock)`):
  - `Open` store (single handle, `store.Open(ctx, filepath.Join(canon,".haro","store.db"))`), `project.LoadConfig` for harness defaults.
  - `Ensure .haro/{artifacts,worktrees,store.db}` via `project.Init` idempotent.
  - `Listener: net.Listen("unix", sock)` (remove stale before bind; `chmod 0600`), `defer os.Remove(sock)`.
  - Signal trap: `signal.Notify(c, SIGTERM,SIGINT)` → `ln.Close()` + `store.Close()` + cancel background goroutines.
  - Accept loop: `for { conn, _ := ln.Accept(); go handleConn(conn, store, adapterMgr, engineFactory) }` where `handleConn` reads NDJSON line-by-line with per-conn `bufio.Reader` + `codec.DecodeMessage` with `MaxMessageSize` check; on oversized/malformed, reply `RPCError{Code:-32700 Parse error|-32600 Invalid Request}` via `EncodeError(id, err)` and **continue** (do not close healthy connection) — read next line.
  - Per-connection write mutex to interleave `EncodeResponse` and `EncodeNotification` safely.
- **Health** (`internal/ipc/health.go`): before full method table, daemon handles `method=="health"` without store; later merged into main dispatch (idempotent). Existing `HandleConn` becomes `HandleHealthConn`.

#### Socket protocol

- **Framing**: NDJSON (one JSON value per `\n`), same as `jsonrpc/codec.go` already does (`encodeAndWrite` appends `\n`, `DecodeMessage` reads until `\n` or EOF, enforces `MaxMessageSize`). Concurrent clients: each has own `Reader`+ write `Mutex`. Server tolerates one malformed line (reply error, continue); oversized → `Code -32700`, truncate input and continue on next line.
- **Dispatch**: map `method → handler(reqID, params, conn)`. For request methods, reply single `EncodeResponse/EncodeError` with same `id`; for notifications (`id==nil`), never reply. Validate `jsonrpc=="2.0"` first; on violation `-32600`.
- **Request structs** (U-04 boundary):
  ```go
  type ExecStartParams struct { WorkflowPath string `json:"workflow_path"`; WorkspaceOverride *WorkspaceConfig `json:"workspace_override,omitempty"` }
  type ExecStatusParams struct { ExecutionID string `json:"execution_id"` }
  type StepRunParams struct { ExecutionID string `json:"execution_id"`; StepID string `json:"step_id"`; Mode *string `json:"mode,omitempty"` }
  type StepEventsParams struct { ExecutionID string `json:"execution_id"`; StepID string `json:"step_id"`; SinceCursor int `json:"since_cursor"` }
  // approve/cancel/reopen mirror spec §6
  ```
  Decode each with `json.NewDecoder(bytes.NewReader(rawParams)); dec.DisallowUnknownFields(); dec.UseNumber()` to catch unknown keys and numeric precision; then field-level validation before any `WithTx` (fail-closed).
- **Error codes**: `-32700 Parse error`, `-32600 Invalid Request`, `-32601 Method not found`, `-32602 Invalid params`, `-32000 Store error`, `-32001 Lease expired`, `-32002 Interaction conflict`.

#### Event / cursor model

- Cursors are **monotonic per scope** (`NextTransitionCursor` and `NextAttemptCursor` as `MAX+1` + UNIQUE index) already proven in store.
- For `step.events`: broker handler resolves **current attempt** for that `execution_id,step_id` (`Attempts` ordered by `started_at DESC LIMIT 1` where `step_id` matches) — if none, returns `{events:[], next_cursor: since_cursor}` (idempotent). Otherwise calls `Events.ListAttemptEventsSince(ctx, attemptID, sinceCursor)` (new repository method needed; today `ListTransitions` exists but no attempt-list helper) returning `[]AttemptEvent` where `cursor>sinceCursor` ordered by cursor. `next_cursor` is `last.cursor+1` or `sinceCursor+1` if empty. Retry of same `since_cursor` yields identical slice (stable pagination). `U-01` ensured by inserting `AttemptEvent` under `WithTx` before response computed; broker never infers cursor beyond `MAX`.
- For `step_transition_events`: either fold into `step.events` as synthetic events (`to_status` deltas) or keep separate method `execution.status` uses `ListTransitions`; recommended to **merge** into `step.events` result with typed envelope `{type:"step_transition", from_status, to_status}` so F-04 tests see both streams through one cursor space — if ambiguous, keep separate and define test accordingly (decide at proposal).

#### Interaction CAS shape

- Creation: when adapter session emits `permission_requested` (future supervised), broker `interactions.Create(ctx, {id:uuid, attempt_id, type:"permission", status:"pending", idempotency_key: uuid})` — out-of-scope for now; for this change approve skeleton accepts **already existing pending interaction** seeded by tests via direct `store.Interactions().Create` (or via `agentHost` path in CLI-direct enabling harness).
- Resolution: `step.approve` handler validates `{execution_id,step_id,interaction_id,decision,idempotency_key}` boundary, loads `interactions.Get(id)`, checks `attempt_id` belongs to that execution/step (identity crossing → `ErrUniqueViolation`/`-32002`), checks `decision ∈ available_decisions` (fail-closed: unknown→ reject without state change), then calls `interactions.Resolve(id, providedKey, decision)` which is CAS idempotent (same key→same result, different key on same `id`→rejected). Return `{resolved:true}` or `{resolved:false}` idempotently; second identical call returns same `decision` without re-executing harness logic.
- Cancel: `step.cancel` loads `attempts` for step's running attempt, calls any held `adapter.Session.Cancel()` (map `attemptID→Session` kept by `runStepAsync`), updates `attempts.status:="cancelled"` with `ended_at`, `transitionStep(...,"running","cancelled")`, and marks lease expiry so later `Renew` fails.
- Reopen: `step.reopen` handler delegates to `engine.ReopenStep` (already implements `InvalidateByStep` cascade over flattened DAG, `step_transition_events` audit, `current_generation` bump) and returns `{invalidated: []string}` derived from `ListByStep` where `invalidated_at != nil && invalidated_by_step == reopenedID`. Optional `feedback string` param accepted (F-08) and stored as bounded evidence for the next `step.run`'s reconstruction path.

#### Fencing on death

- Lease ownership = broker's unique `brokerID = uuid.NewString()` at daemon start, stored in-memory plus `Holder` column.
- On `execution.start`/`step.run` the broker `Leases.Acquire(ctx, execID, stepID, holder=brokerID)` getting `token`. Token recorded in `leases` row and also held in `runningAttempts[attemptID]={holder, token, stepID}`.
- Heartbeat goroutine: `time.Ticker(30s)` → for each running attempt `Leases.Renew(ctx, ..., holder, token)` (single UPDATE WHERE holder+token). If `Renew` returns `ErrNotFound` (row removed or token rotated), mark attempt `expired`.
- Broker death: OS kills daemon → socket closed, `Lease.Renew` stops, rows enter `now > expires_at` state (expires_at ~1m future). Any later write attempt via restarted broker that manages to reuse old `attemptID` with old token is rejected (`Renew` check fails) or `completeAttempt` guard checks `lease.Get` expiry before write and returns `-32001` with guidance "lease expired, run resume/reopen".
- Clean shutdown: `SIGTERM` → iterate `runningAttempts` → `Leases.Release(ctx, ..., holder, token)` (sets `expires_at=now`) + `os.Remove(socketPath)` + `Listener.Close()` — next launch succeeds immediately (no zombie).

#### Notification mechanism

- Non-blocking notifications are required by F-09: `step.status_changed{execution_id,step_id,from,to,cursor}` and `step.interaction_required{...,interaction_id,kind,description,options}`.
- Minimal V1: piggy-back on `step.events` polling (CLI loops `step.events` with small delay; server has no push). F-09 tests can subscribe by repeatedly calling `step.events` after `step.run` and observe notifications as typed events in same paginated sequence.
- V2 push (added without breaking V1): per-connection subscription map `subs[execution_id:step_id] → chan Notification`. After each `CreateTransition` or `CreateAttemptEvent` of relevant type, broker fans out `EncodeNotification(conn, method, params)` on each subscribed `net.Conn` under write lock. `jsonrpc/codec.go:EncodeNotification` already emits correct shape (`jsonrpc:"2.0", method, params` no id). Connection closed → unsubscribe.
- For TDD: test can hold a long-lived connection, issue `step.run` on a second conn, and assert `DecodeMessage` on the first returns a notification frame before the response on the second (race careful: use `sync.WaitGroup`).

#### Future-proofing for ACP (not implemented now)

- Broker keeps `adapter.Manager` lifecycle separate from RPC layer: `internal/broker/runtime.go` owns `Store`, `AdapterManager`, and `SessionRegistry map[attemptID]Session`. When step 4 (supervised) arrives, broker will add `SessionHost` that calls `session/request_permission` → `interactions.Create` → notification, and the adapter's `Initialize` info will flow from `Manager.ProbeResults`. Current CLI-direct `agentHost` is kept as `broker/noopHost` implementing `SessionHost` with fail-closed default until real ACP transport is wired. This satisfies the preamble: broker's adapter-facing surface does not preclude ACP but does not implement ACP dispatch yet.

## Open Questions

1. **Where should `store.db` vs socket live for cross-worktree / git-worktree execution?** Current derivation uses `canonRoot`→`/tmp/haro-<h>.sock` but `store.db` remains `canonRoot/.haro/store.db`. For worktrees (`git worktree add --detach` at `engine.CreateExecution`), `canonRoot` may diverge (`evalSymlinks` of worktree path vs repo common dir). Decide: socket key = git-common-dir's `SHA256` vs checkout root — otherwise one logical project would spawn two brokers. Preference: `git rev-parse --git-common-dir` fallback under `.haro/` derivation, else `canonRoot`.

2. **Cursor space for `step.events` — attempt-level already chosen, but should it namespace `step_transition_events` into the same `since_cursor`?** `v2-no-regresion/F-09` says events with cursor persisted before visible (both attempt and transition). If we merge streams, `since_cursor` must be global per `(execution_id,step_id)`. Alternative (cleaner): `step.events` serves only `attempt_events` of the current attempt; status transitions are observed via `execution.status` polling. Proposal should pick and lock.

3. **Feedback transport for reopen without re-run — string vs file ref?** Deltas say `step.reopen with feedback` for next attempt; engine already truncates prior + delimited feedback within 2 MiB in-memory. Should `step.reopen` JSON param be `{feedback: string, max 2 MiB}` inline or `{feedback_ref: path}` pointing to `.haro/feedback/`? Inline is simpler (NDJSON handles bounded 2 MiB comfortably under 10 MiB MaxMessageSize) — confirm inline is intent.

4. **Adapter manager residency — broker holds adapters or still CLI?** Constitution V says broker manages sessions and bridges CLI↔adapters; tech spec §7 says `SessionHost is implemented by the broker`. Easiest day-1: broker owns `adapter.Manager` (moved from `internal/cmd/execute.go:injectAdapterManager`). Implication: broker detachment inherits `project.LoadConfig` caching and `Probe` side-effects; CLI becomes thin. Confirm migration is in scope vs adapter residency deferred to step 4.

5. **Signal semantics on broker death — who reaps leases?** Today `Leases.Release` is broker-initiated; on death we rely on expiry (`expires_at`). Should a fresh broker on startup scan `SELECT * FROM leases WHERE expires_at < now` and `Release` stale rows, or let `Acquire` overwrite with `token+1`? Risk of holding stale `shared` path_claims as well — needs explicit `broker: OnStart prunes expired leases+claims` step.

6. **Named-pipe portability — support Windows in this change or gate as `GOOS != windows`?** UDS path on Windows must use `npipe`. If CI runs only Linux/macOS, we could defer Windows to a later verification; but `deltas-acceptance.md:U-01/U-02` imply Windows parity. Decide to include build-tagged `socket_windows.go` with `go-winio` pure Go (no cgo) now vs `skip:windows` test gate.

7. **Backwards compatibility — should CLI fallback to direct `Store.Open` when broker unreachable and `HARO_NO_BROKER` not set?** For resilience in tests/CI (where many `t.TempDir()` repos spawn short-lived brokers), a fallback hides broker launch failures. Recommendation: no fallback in production; `HARO_NO_BROKER=1` only for hermetic unit tests; `EnsureBroker` failure must be visible (structured `broker_startup_failed` error) to keep v2-broker failures honest.
